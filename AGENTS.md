# mirror / 观己 — Agent Guide

## Product direction

- Chinese MBTI-style self-exploration site, designed for WeChat mobile first and adapted to PC. English is the default at unprefixed URLs, while Chinese uses `/zh`; both languages share every layout. English orders use `PRICE_USD_CENTS` (default $6.9) and the configured English payment provider.
- Visual system is fixed: cool gray paper `#edf2f3`, near-black ink `#171b1c`, black editorial report `#121718`, warm accent `#c49473`, thin radar chart, pill-shaped primary actions, Manrope for Latin + system CJK fonts. The UI review of 2026-09-23 (owner request: "解决所有视觉/链接问题") tightened it into rules:
  - **Text colour is a token, never a hex.** On paper: `ink` (primary), `slate` `#3f4b50` (reading), `mist` `#5d696d` (secondary, 5:1). On night: `paper`, `night-body` `#b4c1c5`, `night-mist` `#8d9ca1`. `warm` is only 2.4:1 on paper, so it marks (rules, dots, numbers on night) and `warm-ink` `#8f6242` carries warm text on light surfaces. Nothing lighter carries text.
  - **Type has a floor and a scale.** Nothing is set below 12px (`eyebrow` is 12px). Use Tailwind's size scale (`text-xs`…`text-5xl`); `text-3xl` is fluid (24px at 320, full 30px from 500px). Size utilities inherit `--leading-body` / `--leading-heading`, and headings `--tracking-heading`, all set per language on `html:lang(en)` (Chinese 1.75 / 1.45 / −0.02em, English 1.6 / 1.2 / −0.025em, English `text-3xl` a step smaller). Don't hand-set `leading-[…]` or `tracking-[…]`. English eyebrows are set in capitals by the utility.
  - **Headings never break inside a Chinese word**: the site's own `h1–h3` use `word-break: keep-all` + `text-wrap: balance`, so they break at punctuation; a heading with no internal punctuation that cannot fit carries an explicit `\n` in its copy. Quiz items (`#question-title`) and published share lines (`[data-share-card]`) keep normal breaking — their clauses can outrun a narrow line, and an emergency break there would start a line with “，”. Paragraphs use `text-wrap: pretty`.
  - **One dark moment and at most one warm fill per page.** Dark (`bg-night`) is for the result reveal, the report's chapter covers, the unlock panel and the sample CTA; everything else is paper or `bg-card`. `warm-panel` fills one closing moment; elsewhere warm is a 2px left rule. No paper-grain texture and no cropped brand relief — both were removed.
  - **Links always look like links.** `TextLink` (`site/text-link.tsx`) renders the label with a trailing arrow: → stays on the site, ↗ (`external`) leaves it. `PrimaryButton` uses → by default and `icon="external"` only for a hosted checkout. Never put `text-link` through `cn()` — tailwind-merge reads it as a text colour and drops it beside `text-mist`; `TextLink` joins classes by hand. The report's current chapter is a warm bar, not an arrow.
- Brand artwork uses the facing mirror contours and warm centre dot in `src/components/brand/brand-logo.tsx`; the outlined lockup is shared by the header and OG images and follows the locale: `mirror / 观己` (viewBox 194) in Chinese, `mirror / look within` (Manrope 500, 13px; viewBox 232) in English. Pass `locale` to `BrandLogo` and size OG logos with `brandLogoWidth(locale, zhWidth)` so both lockups keep one glyph scale. Phone headers (under 721px) show only the mark and `mirror` wordmark, identical in both languages: `BrandLogo tagline={false}` at `brandLogoWidth(locale, 168, false)`, the glyph scale of the 168px Chinese lockup; never put 观己 or look within back on phones. Desktop headers keep the full lockup at 194px in Chinese and 232px in English. `app/global-not-found.tsx` sits outside `[lang]` and uses the English lockup. `MirrorMark` (`brand/mirror-mark.tsx`) redraws the two contours from a result's four scores — the gap follows E/I, height S/N, the centre (ring or dot) T/F, closed or open halves J/P, and a near-even J/P draws dotted inner edges — so every type, and every result, has its own mark. It is decorative (`aria-hidden`) and appears on the result reveal, the report sidebar and phone header, the type index and type pages, history records and the home sample card; `typeMirrorProfile(type)` gives a type's canonical mark. Run `npm run brand:build` after artwork changes to refresh `public/assets/brand/`, `src/app/favicon.ico` and `docs/brand/logo-preview.png`; see `docs/brand/README.md` for variants.
- The reference screenshots in `docs/design-evidence/` are the source of truth for layout, density, spacing and copy. `docs/design-evidence/ui-review-2026-09-23/` (393×852 and 1363×936, from a production build) supersedes the originals for the home, quiz, result, report and type pages reworked that day. Do not change copy strings, pixel values or colors without a matching screenshot or explicit user request.
- The home hero keeps text legible over the portrait without dimming the rest of the photo (user request, 2026-09-15). Phones: a paper scrim behind the copy (solid at the photo's 220px top edge, 82% under the last line, fading out over 120px) and a paper fade behind the fixed dock, whose free label and sample chip (a 20px mark, 示例结果 and the sample's type, linking to `/result/sample`) are slate `#52656e`. Desktop: a sample result card (INFJ, its mark and four scores, linking to `/result/sample`) sits on the photo's lower corner away from the face — left in Chinese, right in English; it replaced the two decorative captions. Each language has its own portrait: `src/assets/portrait.jpg` (English) and `src/assets/portrait-zh.jpg` (Chinese; Pexels 3754248, its warm wall regraded to the paper tone so the background matches the page — see `docs/brand/README.md`). `pageMessages.home.portraitAlt` describes each, and the home OG card reads the same file through `portraitDataUrl(locale)`. Recheck WeChat height 390×749 and English copy (four description lines) after changing either portrait or the hero copy.
- The paid report price is `PRICE_FEN` (default ¥6.9) / `PRICE_USD_CENTS` (default $6.9). **Nothing before the test may quote a price or hint that anything is sold** (owner decision, 2026-09-17). Home, quiz, `/result/sample`, `/report/sample`, `/about`, `/preferences`, `/types` and both `llms` files say the test is free and stop there — no amount, and no 付费 / 解锁 / 订阅 / 续费 / paid / unlock / subscription. The home JSON-LD keeps only the free Offer and the sample `Product` has none, because the pages no longer show a paid one; `site.description` (every page's meta) says only that the test is free. The amount lives on the purchase surfaces alone: the result page's unlock dock and `UnlockPanel`, `PaymentSheet` and `/pay/[orderId]`, all of which a visitor reaches only after finishing a test. `/help`, `/terms` and `/privacy` still describe payment in full — they inform buyers rather than sell. `tests/e2e/flow.spec.ts` asserts the home and sample bodies match none of those words. In `mock` payment mode every "演示" label must stay; in `wechat` mode they switch to real payment copy. Never present the client-side `unlocked` flag as authorization: `/report/[id]` decides on the server.
- Names (2026-09-24, from the design review): the free result is 测试结果 (Test result), the paid reading is 完整报告 (Full report), the public single-person card is 相处说明书, and the paid reading for two is 双人指南 (Guide for two). Never 配对 / 配对指南 / 详细报告 / 简要结果. S is 实感 (Sensing). Purchase copy names both things unlocked (完整报告＋双人指南 / Report + guide for two), and the unlock bullets come from `unlockBulletsFor(locale)`.

## Stack rules

- Next.js 16 App Router with `cacheComponents: true`. Anything that reads `cookies()`, `headers()`, `params`, `searchParams`, `usePathname()`, `useSearchParams()` or does uncached I/O must sit under a `<Suspense>` boundary or a `loading.tsx`. Route handlers that must never be prerendered call `await connection()` first.
- `src/proxy.ts` (not middleware) issues the signed `mid` visitor cookie. Sign/verify lives in `src/lib/visitor-token.ts`; server code reads it through `src/lib/session.ts`.
- Locales: every page lives under `src/app/[lang]` with the root layout there (`next/root-params` `lang()`; `generateStaticParams` from `publishedLocales` in `src/lib/i18n/locale.ts`). English keeps unprefixed URLs: the proxy rewrites `/x` to `/en/x`; `next.config.ts` 308-redirects old `/en/x` URLs to `/x` before Proxy, while `/zh/x` passes through. Route handlers, `robots`, `sitemap`, the English `manifest.webmanifest`, root `llms*.txt`, `favicon` and the English root `opengraph-image` stay at the app root and in the proxy's `ROOT_ROUTES`. The manifest and home OG image use route handlers rather than special metadata files, so the `[lang]` layout can select each locale's link and image metadata. Each language installs as its own app: `src/lib/manifest.ts` builds both, `app/manifest.webmanifest/route.ts` serves the English one and `app/[lang]/manifest.webmanifest` the Chinese one, and the `[lang]` layout sets `manifest: href(locale, "/manifest.webmanifest")` so the root link never ships English to `/zh`. Unmatched URLs under a language prefix hit `app/[lang]/[...rest]/page.tsx`, whose only job is to call `notFound()` so `[lang]/not-found.tsx` answers in that language (it exports `instant = false`, since a page that only throws has nothing for dev-time instant validation to render); `app/global-not-found.tsx` is the backstop for paths outside `[lang]`. A 404 is a non-streamed response, so every `notFound()` in the app returns the shell and resumes its copy on the client — assert 404 copy through a rendered page, never the raw HTML. Build every internal link with `href(locale, path)`; never hard-code `/quiz`. The language switch is `site/language-links.tsx`, the last group of both 更多 menus in `AppHeader` (user request, 2026-09-24: languages left the nav so 16 型人格 could join it): a 语言 / Language label over plain `<a hrefLang>` options resolved on the server; the current language is checked and not a link. Pass `path` for pages that exist in both languages so each option opens the same page; omit it on language-bound pages (real results, reports, orders, 404), where it opens the other home. Do not derive it from `usePathname()`. Options render only while the menu is open (`useMoreMenuOpen` from `site/more-menu.tsx`), so an English page never carries 中文 in its HTML and the head's hreflang alternates stay the crawler path. The group is a labelled list, never `role="group"` (see the quiz answer group below).
- Header navigation replaces footers: no page renders a footer or a bottom list of links. From 721px `AppHeader` shows 人格测试 · 16 型人格 · 我的报告 · 更多信息; phones show only 更多, whose menu starts with 人格测试, 16 型人格 and 我的报告 (`phonePrimary`; a second phone item overflows at 360–375px or shrinks the logos). The phone logo or back link and 更多 share one centre line, as in `docs/design-evidence/mobile-home.png`: keep each label `items-center` in its 44px tap box and never top-align one (a link with `min-h-11` and no flex centring puts its text at the top). Both menus then list 了解四维偏好, 测试说明, 测试与订单帮助, after a rule 隐私政策 and 用户协议 (`moreGroups` in `app-header.tsx`), and after another rule the languages. `site/more-menu.tsx` is a disclosure button (`aria-expanded`, `aria-controls`) over a panel of server-rendered links that is only `hidden` while closed, so the links stay in the HTML; unlike the language options they have no other crawler path, so never move them into a render-on-open dropdown. Do not use `<details>`: its implicit `group` role would sit on every page and collide with the quiz answer group that tests find by role. The panel closes on an outside press, Escape (focus returns to the button), focus leaving or a followed link, and opening sends `more_menu_open`. The panel is a card with a 160ms entrance and a turning caret, all off for reduced motion. The about sheet now opens only from the desktop home steps bar; `/about` serves everyone else. `tests/e2e/header-nav.spec.ts` covers the HTML links, the primary links on each width, the languages at the end of the menu, closing, the 360px phone fit and the phone header's centre line; `tests/e2e/i18n.spec.ts` switches languages through the menu.
- Copy: page and component strings live in `src/lib/i18n/messages/*` as `{ zh, en }` with `en: typeof zh`, so a missing key fails typecheck; Chinese strings stay verbatim. Server Components read the locale with `getLocale()`; client islands with `useLocale()` (the root layout's `LocaleProvider`). Content modules (`site`, `personality`, `type-context`, `preference-content`, `report-content`, `llms`) take a `locale`. Legacy content helpers default to `zh` to keep Chinese output unchanged; `llms` defaults to `en` for the root files. English type names are the four preference labels (`Introverted · Intuitive · Feeling · Judging`) — never 16Personalities-style nicknames — and English copy says MBTI®-style / not the official MBTI® instrument.
- No English decorative copy on Chinese pages (user request, 2026-09-16). Eyebrows, photo captions, report chapter labels (第一章 / `CHAPTER 01`) and OG kickers are Chinese in `zh` and English in `en`, so every such string lives in `src/lib/i18n/messages/*` — never hard-code one in JSX, and never pair the two languages in one string (`SAMPLE REPORT · 示例报告`). Only MBTI, type codes, dimension letters and the `mirror` wordmark stay Latin. The mirror rule holds for English pages: no Chinese fallbacks, including accessible names such as `ResponsiveSheet`'s close label. `app/global-not-found.tsx` sits outside `[lang]` and uses English, the default language.
- A result's language is its questionnaire's (`questionnaireLocale`): `en32-v1` / `en64-v1` mirror `legacy32-v1` / `standard64-v1` item for item (dimension and reverse flags copied, text only differs). `/result/[id]`, `/report/[id]` and `/pay/[orderId]` redirect to that locale; orders take price, currency (`CNY` fen / `USD` cents), provider and messages from it. API messages that precede a known result use `requestLocale()` (same-origin `Referer`).
- `/my/report` renders every result owned by the signed visitor, newest first, including unpaid summaries. Order-number recovery is folded away by default (most visitors arriving empty simply haven't tested yet); `/help` links to `/my/report?recover=1`, which opens it. Never infer history from localStorage. Full order numbers are bearer recovery credentials: `POST /api/reports/recover` restores the order's visitor cookie for any order status, but never unlocks a result. Keep order numbers owner-only, the same-origin check, database-backed rate limit, and fresh navigation after recovery; the proxy must not overwrite this response's restored cookie.
- Tailwind v4 with tokens in `src/app/globals.css` (`@theme`). Breakpoints are `md` = 721px, `xl` = 1101px, `2xl` = 1450px to mirror the prototype's media queries. Mobile-first: base classes are the phone layout, `md:` is desktop. Prefer the theme scale and tokens over arbitrary values (see the visual rules above); keep arbitrary values for layout geometry only. A `short` variant (`max-height: 760px`) compacts the quiz for WeChat's visible height. Shared patterns are `@utility` (`eyebrow`, `pill`, `text-link`, `back-button`, `pb-safe-4`).
- Light pill buttons keep a light background on hover (`paper` / `#edf2f3`) so their ink text stays readable in dark CTA sections; never inherit the dark pill hover fill. They are for dark surfaces only: on paper or a card a light pill has no visible edge, so use a dark pill or a text link there.
- Focus rings are 2px warm-ink on paper (warm alone is under 3:1 there) and warm inside `.bg-night` / `.bg-night-deep` (`globals.css` base layer).
- Loading screens (`loading.tsx` for result, report, pay and history) reuse their page's frame through `site/skeleton.tsx` (`Skeleton` in paper or night tone, `RadarFrame` for the radar's empty grid), so content lands where its placeholder stood; the pulse stops for reduced motion.
- `/pay/[orderId]` leads with the order's state as its h1 (icon, label, one line of what happens next, in a `role="status"` block), then the order line, the fee rule and one action: read or invite when paid, a text link back while pending, a retry pill after a failed payment.
- Motion is restrained and finite: home title lines enter 90ms apart, the portrait settles from 1.025× in 1.1s, and report chapters enter in 280ms. Keep CTAs and fixed docks outside animated ancestors. Radar SVG and data stay server-rendered; its small client shell only coordinates a single 720ms reveal per mounted chart, including when scrolled into view. Preserve the complete static fallback, respect reduced motion, and never replay a finished chart merely because a chapter becomes visible again.
- Interaction motion: question content enters from ±8px over 240ms, with direction shared by next/back/review navigation. **An answer moves on by itself** (owner decision, 2026-09-23): 280ms after a choice — long enough to see it confirm — the next question slides in. The timer re-reads the saved draft, so the answer is never lost, and any other navigation (back, next, review jump, version switch, unmount) cancels it. The last question never submits by itself: the result is always one deliberate tap. Keyboard focus follows into the new question's answers. Press/check feedback lasts 160ms. On phones the strengths switch moves its background in 240ms and fades the visible list in 200ms, retaining both server-rendered lists; from 721px chapter 02 sets each strength on one row with its blind spot (`data-strength-columns`) and has no switch. Desktop dialogs use a stationary fading overlay and a 240ms entrance / 180ms exit; let Radix manage presence and Vaul manage phone drawer gestures. Disable these animations for reduced motion, and limit hover movement to fine pointers.
- Quiz counters use `NumberMotion`: only changed digits roll for 240ms, increasing upward and decreasing downward. Accessible text always exposes the latest number once; decorative old digits are hidden for reduced motion and print. Do not count through intermediate values or queue transitions. Carry the old total across the version picker so 32/64 changes animate without merging drafts. Version-card copy enters in 280ms with a 60ms offset for the second card; its CTA stays outside the animation. Quiz progress settles in 360ms; accordion content opens/closes in 240/200ms using Radix's measured height.
- shadcn/ui primitives live in `src/components/ui/*` and are restyled to the prototype; add new ones with `npx shadcn@latest add <name>` then restyle. Icons come from `@phosphor-icons/react` (`/dist/ssr` in Server Components).
- Client islands are small and explicit: `quiz/quiz.tsx`, `result/result-actions.tsx`, `payment/*`, `report/chapter-ui.tsx`, `site/site-overlays.tsx`, `site/language-links.tsx`, `site/more-menu.tsx`, `quiz/result-reveal.tsx`, `brand/mirror-morph.tsx`, `report/report-image.tsx`, `report/continue-reading.tsx`, `analytics/page-views.tsx`, `analytics/track-view.tsx`. The report is the case to watch: `report/report-body.tsx` is a Server Component that renders **all four chapters plus both the strengths and the blind-spot lists**, and `report/chapter-ui.tsx` only toggles which one is visible. Each version has its own draft; memory fallback must allow completing the current quiz when localStorage fails. Keep next (for revisiting answered questions), answer review and a confirmed restart of only the current version.

- **Every completed questionnaire yields four letters** (owner decision, 2026-09-21). Nothing withholds a type or a purchase: there is no `UNCLEAR_RESULT`, and `hasClearPreference` is gone. An exact 50 breaks to I / N / F / P, the published MBTI convention — `SCORING_VERSION` is `preference-v2` because of it. Uncertainty is carried by `clarityOf`, four display bands on a dimension's score: `even` (50–55), `balanced` (56–60), `slight` (61–74), `marked` (75+). `even` and `balanced` together are exactly the stored `balanced` flag, so old rows keep their meaning. When every dimension is balanced the type is presented as a reference only — `profileMeta` swaps in the all-even line and summary, `TypeIntro` shows `allBalanced`, and a published share snapshot always carries a `typeNote`. A partly balanced result keeps its type's own line and summary (2026-09-23: most results have at least one near-even dimension, so replacing the copy meant most people never read their type); `TypeIntro` names the balanced pairs in one line (`balancedNote`), and each dimension's reading, radar axis and stat carries its clarity band. Radar axes and stats always name the leaning pole (`直觉 N`), never `S / N`. The bands are a display convention, not validated confidence. `uniformAnswers` flags a long run of one option (≥ 3/8 of the items) and the result page answers it with a non-blocking review invitation — it never withholds a result, a type or an unlock. Never remove access to an existing paid report. Paid content uses strength, near-balance, contextual examples and seven days of practice; retain all content in server HTML. Neither questionnaire is a validated or official MBTI instrument; 96-item and A/B versions await user trials.

Type pages explain with diagrams from `components/types/type-diagrams.tsx`, all server-rendered: `LetterBreakdown` (each letter over its preference) in the hero, `DimensionSpectrum` (which side of each pair — a type page encodes side, never strength, since it describes no one's scores), `EverydayFlow` (energy → information → judgment → planning), `MisconceptionList` (tagged by letter), `SayItBubble`, `NeighborTree` (the four one-letter neighbours with the letter that flips) and `TypeMap` marking the type and its neighbours. Type pages use the type code as H1 (Chinese adds its name inside it; English doesn't, since the letter breakdown already spells out the four labels) and open the context section with a self-contained “XXXX 是什么意思？” definition from `typeContext().definition`. JSON-LD must describe only visible facts, in the language of the page carrying it: `organizationJsonLd`/`websiteJsonLd` in the `[lang]` layout take the locale, and `websiteId(url, locale)` gives each language version its own `WebSite` node (`#website` / `#website-zh`) so the two cannot overwrite each other. The organization is one entity — one `@id`, one `url`, one logo — with only its name and its `contactPoint.url` following the page. Build absolute JSON-LD URLs with `absoluteUrl(baseUrl, locale, path)`. `tests/e2e/i18n.spec.ts` asserts no English page renders a CJK character anywhere, including the flight payload, so a Chinese string reaching a client island fails there. `robots.ts` keeps one `*` group so AI answer crawlers can cite public pages; a bot-specific group would need to repeat every disallow.
- Public support email is configured once in `site.supportEmail` and linked from `/help`, privacy and terms. Home visibly says MBTI 测试体验; `/preferences` explains scores and retesting. Preserve the shared brand artwork, colors and sample/paid page architecture when expanding these flows.
- Payments: `src/lib/payments/index.ts` resolves a provider per mode — Chinese orders use `PAYMENT_PROVIDER` (mock | wechat), English orders `EN_PAYMENT_PROVIDER` (mock | crypto | waffo) — and `refreshOrder` always queries the provider stored on the order. One provider is active per language, so `waffo` replaces the crypto checkout on the unprefixed English site rather than sitting beside it. The WeChat adapter is self-contained under `src/lib/payments/wechat/` (Node `crypto` only). Keep `crypto.ts` pure so it stays unit-testable. In mock mode English copy keeps its visible “Demo” labels, like 演示.
- Card payments (`src/lib/payments/waffo/`) go through Waffo Pancake, the merchant of record for English orders: `createPayment` locks a checkout session priced from `PRICE_USD_CENTS` (tax added on top, so the callback’s `subtotal` is what we charged) and returns a `redirect` payload; the buyer leaves for the hosted checkout and returns to `/pay/[orderId]`. Never build a card form on-site — that would pull the app into PCI scope. `/api/payments/waffo/webhook` verifies the RSA signature over the **raw** body, stores the event as `<eventType>:<eventId>` for idempotency and drops the buyer’s email before storing. **There is no refund flow** (owner decision, 2026-09-17): refund events are recorded and never revoke a report, and the sheet, terms and privacy policy say up front that purchases are final. A callback or poll that lands after the order expired still unlocks it — the card was already charged.
- Crypto payments (`src/lib/payments/crypto/`, viem + `@solana/kit`, both MIT; no gateway and no WalletConnect/Reown, whose licenses are not open source) pay the configured receivers directly and are read back from the chains. Invariants: Solana orders carry a unique Solana Pay `reference` and pay when a successful transaction referencing it raises the receiver's USDC/USDT balance by at least the price; Ethereum orders pay only from the wallet that signed the order's challenge (`POST /api/orders/[id]/payer`, set once, verified via the RPC so smart wallets work), counting accepted-token `Transfer` logs from `start_block` with `ETHEREUM_CONFIRMATIONS`. Providers return candidates and `claimPaymentEvent` (unique `payment_events.event_id`) lets one transfer pay one order only. Crypto orders last 30 minutes, are checked before expiring and for 24 hours after, and chain reads are throttled per order. Keep matching logic pure (`amounts.ts`, `solana-pay.ts`, `ethereum.ts`) with unit tests. Wallet deep links carry only the public page URL — never an order number — and buyers restore the test in the wallet browser with the recovery form.
- Analytics is GA4, started before hydration by `src/instrumentation-client.ts` → `src/lib/analytics/track.ts` (gtag queue, ads consent denied, Google signals off, `send_page_view: false`, gtag.js loaded after `load`). `NEXT_PUBLIC_GA_MEASUREMENT_ID` is inlined at build time; without it events only queue in `window.dataLayer`, which the e2e tests read. `analytics/page-views.tsx` sends one `page_view` per pathname (not per `?chapter=` / `?unlock=1`), `analytics/track-view.tsx` records views from Server Components, and every other event is typed in `src/lib/analytics/events.ts` and documented in `docs/analytics.md` — add new events to both. Server-rendered CTAs spread `trackAttrs(cta, location)` and a delegated listener sends `cta_click`, so tracking never turns a Server Component into a client one. Privacy invariants: `page_location` / `page_referrer` pass through `sanitizeLocation` / `sanitizeReferrer`, which replace result IDs and order numbers and keep only attribution parameters; `purchase` uses a one-way hash as `transaction_id`; never send answers, scores, personality types, order numbers, openids, wallet addresses or transaction hashes — the privacy policy promises results are not shared. Update the privacy policy when the data sent changes.
- OG images render with satori; fonts are the TTFs in `src/fonts/`. After changing Chinese copy that appears in OG images, run `node scripts/build-og-fonts.mjs` to refresh the CJK subset.

## Sharing and comparison invariants

- P0 single-person sharing stays free. New pairing uses `paid-pair-v2`: both signed visitors must have unlocked the exact results used, including previously purchased results. `legacy-free-v1` guides retain original reading/withdrawal rights; old invitations accept no new participants. Payment never substitutes for either separate consent (`compare-host-v3` / `compare-guest-v2`).
- Invitations may be created directly from a paid result with no parent share. Owner pages expose result/report/management entry points; no hidden P0 card is created. Server continuations save only intent and survive payment/identity recovery; multiple invitations require an explicit choice. A paid order with missing result access offers reconciliation, never a second purchase. Keep the success actions when a dialog becomes a phone drawer.
- The result page is ordered around the report: reveal + chart, then (desktop, locked results only) `UnlockBar` with the price and the unlock button right under the first screen, the four dimension readings, `UnlockPanel`, then the guide for two as something the report brings (`PairingBenefit`, three outputs and a link to `/pairing`), then sharing. `UnlockPanel` previews what the report says — each chapter's first line from `reportPreview()`, cut to a teaser on the server so the page never carries more — rather than listing promises. The paid report opens straight onto chapter 01's dark cover; the invitation above it is a one-line strip (`PairingBenefit compact`). Each chapter is a dark cover (label, heading, lead) over reading on paper. Chapter 01 is its own reading (per dimension: the strength used and one thing to try, or both ends when near-even), not a repeat of the result page. Chapter 04's seven days are a checklist whose ticks live only in this browser (`mirror.practice.v1`, `report_practice_check`); pending pairing continuations sit after the report reading so its title remains on the first screen. The relationship chapter also has an invitation entry outside its animated content. English phone chapter labels wrap within their four columns, retaining full accessible names; Chinese labels keep their existing layout.
- Public `/pairing`, invitation metadata/copy, and invitations seen before testing introduce value without purchase language. On an owned result and before payment, clearly explain that both people unlock their chosen reports. This follows the latest pre-test product rule. Pairing produces frozen communication prompts; never a relationship score.
- A pair guide is `compare-v3` (`src/lib/compare-content.ts`): one emphasis (the dimension worth saying first, with the single quote the reading is built around), **one card per dimension** in `COMPARE_DIMENSION_ORDER` carrying that dimension's relation, body and a concrete scene, then one shared practice. Every consented category reaches the reading, so the four categories a partner brings produce 81 distinct readings rather than varying only the emphasised one — `tests/unit/compare-content.test.ts` asserts that count, plus role symmetry over all 6,561 pairs. Output stays role-neutral ("一方 / 另一方") because the two readers share one row; who is who is presentation, passed to `ComparisonReading` as `sides` from the already-visible snapshots. Deepening the guide again needs `compare-v4`: `ComparisonReading` renders stored `compare-v1` and `compare-v2` through their own `sections` path and never re-renders them as a v3 reading. The consent versions (`compare-host-v2` / `compare-guest-v2`) do not move with the content version — the scope they cover is unchanged.
- The fictional example (`PairingExample`, on `/pairing` and `/t/[token]`; the result-page benefit links to `/pairing` instead of embedding it) is one level deep — the two voices are quotes, the reading brings its own cards — and is always a preview: the emphasis plus the one emphasised card and `moreDimensions`, never the four-card reading a pair receives. A free surface must not show the whole paid reading.
- Reader-facing surfaces never print a questionnaire id: `PreferenceSummary` names the version with `questionnaireName()` and `pageMessages.history.version`, as every other page does. The consent scope it shows (four categories, questionnaire version, test date) stays complete but compact, and on `/compare/[id]` it follows the reading so the emphasis leads the page.
- A pair can take their guide away: `/compare/[id]/image` renders the emphasis, its quote and the shared practice as a PNG, owner-only through `getOwnedComparison` like the page itself. It is built from the frozen reading alone — never from either `CompareSnapshot` — so no categories, questionnaire version or test date can reach an image that may be forwarded, and the QR carries the public `/pairing` URL, never the private guide. The page says what the image contains. Its exits (invite someone else, save the image) sit above the consent scope; withdrawal stays last.
- An invitation may carry `host_note`: one optional line the host writes, capped at `HOST_NOTE_MAX` and normalised by `hostNoteSchema` to a single line of printable text (an empty note is simply absent). Anyone holding the link reads it, so it is published under its own host consent version — `compare-host-v3`, whose detail copy names it — and it is part of the invitation's idempotency hash. It renders on `/t/[token]` above the heading and nowhere else: never in `generateMetadata`, never in the OG card, never in an analytics event, because previews are fetched and cached by third-party servers. React escapes it on render; the schema's job is one printable line, not sanitising markup.
- `/t/[token]` has its own OG card (`src/lib/og/invitation-image.tsx`), because a forwarded invitation otherwise previews as the generic home image. It renders only invitation copy — link previews are fetched and cached by third-party servers, so no host categories, dates or tokens belong in it. Its Chinese copy is in the OG font subset (`scripts/build-og-fonts.mjs` reads the compare and pairing message modules); re-run that script after changing it.
- `/s/[token]` reads only the immutable public snapshot. Optional type/dimension fields are omitted when disabled; never pass result IDs, candidate IDs, scores, orders or visitor IDs to public output. Tokens use 24 random bytes; owner mutation still requires the signed visitor.
- `/t/[token]` has separate host consent for four qualitative categories, questionnaire version and test date. `/compare/[id]` is readable only by its two signed visitors. Lock mutation ancestors in share → invitation → pair order; expiry prevents new joining, withdrawal invalidates existing access.
- First-result referral updates run in a nested transaction/savepoint. An analytics SQL error must not abort the result transaction or allow a later retest to claim the missed first result.
- New sharing pages keep complete server-rendered content. `StaticStreamFallback` exposes only containers marked `data-share-static` when JavaScript is disabled; its rules belong to Tailwind's base layer so `[hidden]` reset priority cannot suppress the fallback. It changes presentation only after server authorization.
- Sharing motion is a finite WAAPI enhancement over the visible final state, with no CTA/dock inside animated content. Tests wait for the actual animation start and completion, including reduced-motion changes and print.
- PNG uses an explicit flex-column wrapper (Satori Fragment children do not inherit browser layout semantics). Verify actual PNG layout and decode its QR after changes, not just HTTP status or image dimensions.
- Capability routes redact URL parameters and disable Google collection; first-party sharing events do not mean a message was actually sent. WeChat SDK sharing remains off unless `WECHAT_SHARE_ENABLED=true` after channel verification.
- The public card and its PNGs carry the result's mirror mark only when the card shows the type or the dimensions: `shareMirrorProfile` (`src/lib/share-mark.ts`) draws it from those published categories, never from scores, so the mark adds nothing the card does not already say.
- A pair guide places both people on each dimension's two-ended line (`PairScale` in `comparison-reading.tsx`: 你 a filled dot, the other a warm ring, qualitative positions only, with an sr-only sentence), and the emphasis card shows both marks from `categoryMirrorProfile`. The guide PNG still excludes every category.
- `/t/[token]` reads intro → action → example → scope. Its primary action (use an existing result, or start the free test) sits in the phone dock and inline from 721px; the other is a text link.
- `/my/pairing` reads intro → guides → invitations → a new invitation from an unlocked result. Each invitation says where it stands (waiting, how many joined, expired) and offers `InvitationActions`: the editable invitation text first, copying it as the primary action, then copy link and preview, plus a ··· hint inside WeChat.
