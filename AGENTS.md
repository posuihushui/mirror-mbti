# mirror / 观己 — Agent Guide

## Repository layout

- npm workspaces: `apps/web` is the public Next.js app, `apps/admin` is the local admin app and Telegram worker, and `packages/db` owns schema, persisted contracts, migrations and maintenance scripts. Each workspace declares its own dependencies; use the one root lockfile and run `npm install` at the root.
- Product paths below such as `src/`, `public/` and `next.config.ts` are relative to `apps/web`; shared schema and SQL migrations live in `packages/db`. Reference evidence stays in root `docs/`. Do not import between apps or from an app into a shared package.
- Root commands delegate to workspaces: `dev` / `start` run web, `admin:dev` / `admin:start` run admin, `build` builds both, `typecheck` checks all workspaces, `test` runs both apps' unit tests. Environment files belong to their app: `apps/web/.env*`, `apps/admin/.env.local`.



## Product direction

- Chinese MBTI-style self-exploration site, designed for WeChat mobile first and adapted to PC. English is the default at unprefixed URLs, while Chinese uses `/zh`; both languages share every layout. English orders use `PRICE_USD_CENTS` (default $6.9) and the configured English payment provider.
- Visual system is fixed: cool gray paper `#edf2f3`, near-black ink `#171b1c`, black editorial report `#121718`, warm accent `#c49473`, thin radar chart, pill-shaped primary actions, Manrope for Latin + system CJK fonts. The UI review of 2026-09-23 (owner request: "解决所有视觉/链接问题") tightened it into rules:
  - **Text colour is a token, never a hex.** On paper: `ink` (primary), `slate` `#3f4b50` (reading), `mist` `#5d696d` (secondary, 5:1). On night: `paper`, `night-body` `#b4c1c5`, `night-mist` `#8d9ca1`. `warm` is only 2.4:1 on paper, so it marks (rules, dots, numbers on night) and `warm-ink` `#8f6242` carries warm text on light surfaces. Nothing lighter carries text.
  - **Type has a floor and a scale.** Nothing is set below 12px (`eyebrow` is 12px). Use Tailwind's size scale (`text-xs`…`text-5xl`); `text-3xl` is fluid (24px at 320, full 30px from 500px). Size utilities inherit `--leading-body` / `--leading-heading`, and headings `--tracking-heading`, all set per language on `html:lang(en)` (Chinese 1.75 / 1.45 / −0.02em, English 1.6 / 1.2 / −0.025em, English `text-3xl` a step smaller). Don't hand-set `leading-[…]` or `tracking-[…]`. English eyebrows are set in capitals by the utility.
  - **Headings never break inside a Chinese word**: the site's own `h1–h3` use `word-break: keep-all` + `text-wrap: balance`, so they break at punctuation; a heading with no internal punctuation that cannot fit carries an explicit `\n` in its copy. Quiz items (`#question-title`) and published share lines (`[data-share-card]`) keep normal breaking — their clauses can outrun a narrow line, and an emergency break there would start a line with “，”. Paragraphs use `text-wrap: pretty`.
  - **One dark moment and at most one warm fill per page.** Dark (`bg-night`) is for the result reveal, the report's chapter covers (and their small copies on `/my/report`'s record pages), the unlock panel and the sample CTA; everything else is paper or `bg-card`. `warm-panel` fills one closing moment; elsewhere warm is a 2px left rule. No paper-grain texture and no cropped brand relief — both were removed.
  - **Links always look like links.** `TextLink` (`site/text-link.tsx`) renders the label with a trailing arrow: → stays on the site, ↗ (`external`) leaves it. `PrimaryButton` uses → by default and `icon="external"` only for a hosted checkout. Never put `text-link` through `cn()` — tailwind-merge reads it as a text colour and drops it beside `text-mist`; `TextLink` joins classes by hand. The report's current chapter is a warm bar, not an arrow.
  - **Pictures carry the explaining; caveats are said once** (feedback 2026-09-29, "网站文字太多了，需要更多的图片"; owner: apply all suggestions). Spot illustrations live in `src/components/illustrations/`: small still lifes in the brand's arch (a mirror seen from the front) on a 160×120 canvas, ink outlines, the cool tones and one warm accent, in a `paper` or `night` palette (`ILLUSTRATION_PALETTES`). Never a person or a face — a face gives a type an age, gender and look, and a smiling pair reads as a compatibility test — and never text inside a picture, so one set serves both languages and every word stays in the HTML. A scene is a plain function of a palette returning one `<g>`, so `Illustration` draws it on the page and inside Satori (call it as a function there, with `width`). They are decorative (`aria-hidden`): whatever a picture shows is said beside it. Sets: `poleScenes` (one per letter: E voices, I armchair under a lamp, S leaf under a lens, N constellation, T level balance, F two cups and a heart, J ticked calendar, P fork and signpost), `typeScenes` (one per type, drawn from its line: INFJ desk by a window, INFP lantern, ENFJ lighthouse, ENFP kite, INTJ telescope, INTP prism, ENTJ summit flag, ENTP open door, ISFJ umbrella over a plant, ISTJ tidy shelf, ESFJ pot and bowls, ESTJ steps, ISFP palette, ISTP gears, ESFP record player, ESTP bicycle), `relationshipScenes` + `pairScene` (`moment-scenes.tsx`: the moment each relationship's example is about; two chairs under a lamp for an invitation with no relationship) and `restScene` (its own module, for the quiz's client bundle). Where they stand: the result reveal and type page heroes (`night`, `max-w-72`), each result dimension card (both ends over the scale, the leaning end in full and the other at 35%, both in full when near-even), `/preferences` (a tile per pole with its `need`), the type page's everyday flow, report chapter 01's four needs, `/types` cards, `/pairing` (hero and the four relationship cards), `/t/[token]` (its relationship's scene), the 64-item part pause, each record's pages on `/my/report` (the chapter covers, `night`), the type page OG image and the invitation OG card (`pairScene` only — a relationship never reaches an OG card). Caveats a page must keep are said once: the result's percentage notes live behind the ⓘ beside the chart heading (`site/info-tip.tsx`, the native `popover`: no script, text in the HTML, shown in place where popover is unsupported); a result dimension card shows the reader's own line and folds the pair's general description under 了解这个维度 (a `<details>`); `/about` opens with three pictured steps and folds its questions (first one open; answers stay in the HTML and the FAQ JSON-LD). `<details>` is fine off the quiz page — the quiz tests find its answer group by role. The report's summary image is offered as a card showing the picture itself (`report/report-image.tsx`, lazy), and its PNG is `private, max-age=600` so the card and the sheet share one render. **Each scene enters once, then loops** (user requests, 2026-09-29: "给这些插画加一些动画", then "做成循环动画"; the one exception to finite motion). The entrance: it rises in while its arch settles, then its own moment — voices pop in turn, the lamp warms, the constellation draws, the balance tips level, the days tick off; INFJ's sun comes up behind the hills, ENTP's door swings open, ISFJ's umbrella opens, ESTJ's ball hops up the steps, ESTP's bicycle rolls in; the chairs draw up, the tickets slide together, the bars grow. From 1.8s the loops take over, small and never holding still — each moves through its whole round, with no rest inside it (owner, 2026-09-29: "动画没有一直loop") — staggered per part: typing dots, bobbing bubbles, notes, tickets and paper plane, breathing lamp glows, rising steam, twinkling stars, a beating heart, a pulsing circled date, swaying kite, lamps and umbrella, swinging signposts, a waving flag, a flickering flame, dashes flowing along roads and paths, falling rain, the balance and telescope drifting, the clock hand, gears and wheels turning, lighthouse beams and prism rays dimming in turn, lit windows flickering, the lens wandering over the leaf, the bars rising and falling. Parts carry `data-a` + `data-d` (entrance, 110ms steps) and `data-loop` + `data-ld` (loop, 350ms offsets); the keyframes are in `app/illustration-motion.css`, only under `screen` with no reduced-motion preference. Entrances fill backwards only and every loop starts and ends at rest, so the SVG's own attributes are always a real frame: without motion, in print and in Satori a scene is the static drawing. The entrance and loop share one `animation` list (`var(--intro), var(--loop)`), and every hooked part resets both custom properties because custom properties inherit. `SceneSvg` (`illustrations/scene-svg.tsx`, the page's `<svg>`; Satori gets a plain one via `width`) drives `data-scene-motion`: none at first paint (entrance and loops) → `deferred` for a scene off screen or hidden at hydration (nothing runs) → `play` when 15% of it is first in view → `live` once its finite animations end (loops alone, so a chapter shown again never replays the entrance). `data-scene-paused` holds every animation still while a scene is off screen, so only what is visible moves. It marks its own element only after it has hydrated — a page-level script that touched scenes before their Suspense boundary hydrated caused hydration mismatches. A loop must return to rest within its keyframes (a dash loop moves a whole number of dash periods; a gear turns by whole teeth). Never put a hook on an element with a `transform` attribute: wrap it in a `<g>`.

## Stack rules

- Next.js 16 App Router with `cacheComponents: true`. Anything that reads `cookies()`, `headers()`, `params`, `searchParams`, `usePathname()`, `useSearchParams()` or does uncached I/O must sit under a `<Suspense>` boundary or a `loading.tsx`. Route handlers that must never be prerendered call `await connection()` first.
- `src/proxy.ts` (not middleware) issues the signed `mid` visitor cookie. Sign/verify lives in `src/lib/visitor-token.ts`; server code reads it through `src/lib/session.ts`.
- Locales: every page lives under `src/app/[lang]` with the root layout there (`next/root-params` `lang()`; `generateStaticParams` from `publishedLocales` in `src/lib/i18n/locale.ts`). English keeps unprefixed URLs: the proxy rewrites `/x` to `/en/x`; `next.config.ts` 308-redirects old `/en/x` URLs to `/x` before Proxy, while `/zh/x` passes through. Route handlers, `robots`, `sitemap`, the English `manifest.webmanifest`, root `llms*.txt`, `favicon` and the English root `opengraph-image` stay at the app root and in the proxy's `ROOT_ROUTES`. The manifest and home OG image use route handlers rather than special metadata files, so the `[lang]` layout can select each locale's link and image metadata. Each language installs as its own app: `src/lib/manifest.ts` builds both, `app/manifest.webmanifest/route.ts` serves the English one and `app/[lang]/manifest.webmanifest` the Chinese one, and the `[lang]` layout sets `manifest: href(locale, "/manifest.webmanifest")` so the root link never ships English to `/zh`. Unmatched URLs under a language prefix hit `app/[lang]/[...rest]/page.tsx`, whose only job is to call `notFound()` so `[lang]/not-found.tsx` answers in that language (it exports `instant = false`, since a page that only throws has nothing for dev-time instant validation to render); `app/global-not-found.tsx` is the backstop for paths outside `[lang]`. A 404 is a non-streamed response, so every `notFound()` in the app returns the shell and resumes its copy on the client — assert 404 copy through a rendered page, never the raw HTML. Build every internal link with `href(locale, path)`; never hard-code `/quiz`. The language switch is `site/language-links.tsx`, the last group of both 更多 menus in `AppHeader` (user request, 2026-09-24: languages left the nav so 16 型人格 could join it): a 语言 / Language label over plain `<a hrefLang>` options resolved on the server; the current language is checked and not a link. Pass `path` for pages that exist in both languages so each option opens the same page; omit it on language-bound pages (real results, reports, orders, 404), where it opens the other home. Do not derive it from `usePathname()`. Options render only while the menu is open (`useMoreMenuOpen` from `site/more-menu.tsx`), so an English page never carries 中文 in its HTML and the head's hreflang alternates stay the crawler path. The group is a labelled list, never `role="group"` (see the quiz answer group below).
- Header navigation replaces footers: no page renders a footer or a bottom list of links. From 721px `AppHeader` shows 人格测试 · 16 型人格 · 我的报告 · 更多信息; phones show only 更多, whose menu starts with 人格测试, 16 型人格 and 我的报告 (`phonePrimary`; a second phone item overflows at 360–375px or shrinks the logos). The phone logo or back link and 更多 share one centre line, as in `docs/design-evidence/mobile-home.png`: keep each label `items-center` in its 44px tap box and never top-align one (a link with `min-h-11` and no flex centring puts its text at the top). Both menus then list 了解四维偏好, 测试说明, 测试与订单帮助, after a rule 隐私政策 and 用户协议 (`moreGroups` in `app-header.tsx`), and after another rule the languages. `site/more-menu.tsx` is a disclosure button (`aria-expanded`, `aria-controls`) over a panel of server-rendered links that is only `hidden` while closed, so the links stay in the HTML; unlike the language options they have no other crawler path, so never move them into a render-on-open dropdown. Do not use `<details>`: its implicit `group` role would sit on every page and collide with the quiz answer group that tests find by role. The panel closes on an outside press, Escape (focus returns to the button), focus leaving or a followed link, and opening sends `more_menu_open`. The panel is a card with a 160ms entrance and a turning caret, all off for reduced motion. The about sheet now opens only from the desktop home steps bar; `/about` serves everyone else. `tests/e2e/header-nav.spec.ts` covers the HTML links, the primary links on each width, the languages at the end of the menu, closing, the 360px phone fit and the phone header's centre line; `tests/e2e/i18n.spec.ts` switches languages through the menu.
- Copy: page and component strings live in `src/lib/i18n/messages/*` as `{ zh, en }` with `en: typeof zh`, so a missing key fails typecheck; Chinese strings stay verbatim. Server Components read the locale with `getLocale()`; client islands with `useLocale()` (the root layout's `LocaleProvider`). Content modules (`site`, `personality`, `type-context`, `preference-content`, `report-content`, `llms`) take a `locale`. Legacy content helpers default to `zh` to keep Chinese output unchanged; `llms` defaults to `en` for the root files. English type names are the four preference labels (`Introverted · Intuitive · Feeling · Judging`) — never 16Personalities-style nicknames — and English copy says MBTI®-style. That the questionnaire is not the official MBTI instrument (非官方 MBTI 量表) is a footnote, never a selling line (owner request, 2026-09-26: lead with what the test does, not with what it isn't). The home hero, page intros, meta descriptions (`site.description` included) and share / invitation images say what the test does instead: everyday situations, and how far you lean on each dimension.

Only MBTI, type codes, dimension letters and the `mirror` wordmark stay Latin.
