# 微信支付接入与上线执行手册（个体工商户）

> 核对日期：2026-10-08。本方案以中国大陆**个体工商户**申请普通商户，直连微信支付 API v3，适用于本站**中文问卷产生的人民币订单**。仓库已有 JSAPI、H5、Native 下单、通知和查单代码；本次未核验生产开户、产品审批或真实交易验收，[上线前代码门槛](#上线前代码门槛)尚未关闭。本次更新文档，不代表已申请或启用真实收款。

## 个体工商户申请方案

尚未办照时，先按[个体工商户登记与收款申请流程](sole-proprietor-registration.md)准备真实地址、名称、经营范围与登记材料，领照后完成税务和账户准备。

**使用与支付宝方案相同的拟设个体工商户主体，申请微信支付普通商户号及同主体认证服务号，开通 JSAPI 和 Native；本方案不申请 H5。** 官方[主体权限表](https://pay.wechatpay.cn/doc/v3/merchant/4015616699)列明个体工商户支持 JSAPI、Native，不支持 H5。主体具备申请资格，不等于 mirror 的数字报告经营类目已经获准。

| 申请项目 | mirror 的填写方向 |
| --- | --- |
| 主体类型 | 个体工商户，以真实营业执照为准；不按无营业执照的小微商户申请 |
| 接入模式 | 普通商户直连，销售自己的数字服务；当前代码不是服务商特约商户模式 |
| 商户全称 | 营业执照完整名称；mirror / 观己作为品牌及网站关系说明 |
| 经营者与管理员 | 营业执照经营者本人；若授权经办人，按官方流程提交授权 |
| 结算账户 | 优先准备经营者本人银行卡；官方 PC 网站入驻指引允许个体对公或经营者对私账户，最终按后台验证结果绑定 |
| 微信内经营场景 | 同主体认证服务号及其页面内容，申请 JSAPI |
| 电脑网站经营场景 | 真实 PC 网站、域名及所需备案或授权，申请 Native |

官方[PC 网站入驻材料](https://pay.wechatpay.cn/static/applyment_guide/applyment_detail_website.shtml)列明个体营业执照、身份证及银行账户。不能使用他人的普通银行卡收款，也不能把“个体可对私结算”解释成个人微信收钱码可接入本站。

### 经营内容、类目与费用

营业执照的经营范围候选与注册地址要求沿用[mirror 个体工商户方案](plans/mirror-alipay-sole-proprietor-plan-2026-10-08.md#经营范围与商品类目)，微信支付经营类目须另行审核。提交真实示例报告、双人指南及购买流程，优先请审核方确认是否归入“门户论坛/网络广告及推广/软件开发/其他互联网服务”（行业 28）。这属于基于产品形态的申请建议，不能自行认定已经归类。

微信公开[行业及结算规则表](https://kf.qq.com/faq/220228IJb2UV220228uEjU3Q.html)将个体户行业 28 列在规则 746 下，参考费率 **1%**、入账周期 **T+1**，并标注“虚拟限额”。应取得 mirror 实际核准的类目、费率、交易/结算限额及补充资质要求；不能直接按常见的 0.6% 预算。该行业表也说明实际费率以商户平台核准记录为准。普通商户接入申请不收申请费；公众号认证等其他成本单独核实。[申请费用说明](https://pay.wechatpay.cn/static/applyment_guide/applyment_detail_website.shtml)

可提交的商品描述：

> mirror / 观己是性格偏好自我探索网站。用户完成日常情境问卷后，一次性购买对应结果的完整数字报告及双人指南，内容包括偏好解读、优势与盲点、相处及成长建议。普通报告付款后即时开放在线阅读，不提供医疗诊断、治疗或持证心理咨询。请 TA 商品由邀请发起人为参与者购买报告权益，待参与者加入并领取后交付；未领取权益可能转到后续邀请。请确认本业务的经营类目、准入资质及赠送权益审核要求。

普通报告与请 TA 的交付时间不同，应分别展示。审核资料使用示例内容，提供测试后购买页的 ¥6.90 标准价、¥5.50 邀请价和 ¥4.90 请 TA 价格，不提交真实用户报告。产品页面仍沿用现有设计，售价只出现在测试后的购买流程。

## 先决定要开放哪些入口

本站按下单请求的浏览器环境自动选择渠道，运营配置中没有单独关闭某个微信渠道的开关。

| 买家环境 | 当前代码选择 | 个体方案与所需权限 | 买家动作 |
| --- | --- | --- | --- |
| 微信内置浏览器 | JSAPI | 申请 JSAPI；同主体认证服务号并绑定商户号 | 在当前页面调起微信收银台 |
| 微信外手机浏览器 | H5 | 个体不支持；上线前须阻止 H5 下单并提供后续使用指引 | 提示使用微信完成付款；安全续接流程实现前，不承诺打开链接即可续付 |
| 电脑浏览器 | Native | 申请 Native；绑定核准 APPID，满足网站申请要求 | 手机微信扫一扫二维码 |

实际选择逻辑在 [`src/lib/ua.ts`](../src/lib/ua.ts)，中文订单的 provider 由 `PAYMENT_PROVIDER` 决定，英文订单由独立的 `EN_PAYMENT_PROVIDER` 决定。H5 仅适用于微信外手机浏览器；微信内必须走 JSAPI。微信[H5 产品说明](https://pay.wechatpay.cn/doc/v3/merchant/4012791832)明确限定这一点。官方[主体权限表](https://pay.wechatpay.cn/doc/v3/merchant/4015616699)显示，个体工商户和小微商户不能申请 H5；若商户属于这两类，应先设计并实现微信外手机入口的替代处理，再开放真实支付。

**本次仅更新接入方案，代码仍会自动走 H5，不能仅配置 `PAYMENT_PROVIDER=wechat` 就直接上线个体收款。** 上线前须在前端提示和服务端建单同时处理不支持的渠道，不伪造浏览器环境、不让买家长按识别同一手机上的 Native 码。微信外与微信内的访客 cookie 不共享，直接复制私有结果链接不保证有访问权；若设计跨浏览器续接，应安全恢复原访客身份并核对原订单，不能公开订单号或把私有找回凭据放进分享链接。现有订单号找回能力可作为续接设计的参考，但不能代替新的流程验收。

## 第一阶段：申请和后台配置

尚未注册服务号时，先以该个体主体完成服务号注册与认证，再在新商户申请中填写其 APPID，申请 JSAPI / Native；已有普通商户号的，可在认证完成后补申请产品权限。下列事项可提前准备，但产品开通及 APPID 绑定必须依赖已认证账户。

1. **先确认数字服务类目，再申请个体普通商户。** 按上面的资料包及预审描述，在[微信支付入驻指引](https://pay.wechatpay.cn/static/applyment_guide/applyment_index.shtml)提交个体主体、经营者结算账户、真实客服和商品资料。保存获批的商户号 `mchid`、类目、费率、限额及结算安排；确认主体与实际业务一致。
2. **只申请本方案需要的权限。** 在商户平台核实 [JSAPI](https://pay.wechatpay.cn/doc/v3/merchant/4015423216)、[Native](https://pay.wechatpay.cn/doc/v3/merchant/4015614538) 的开通状态。个体方案不申请 H5；本站目前仍自动选择三种，因此先完成微信外手机入口处理再上线。
3. **准备同主体服务号与绑定。** 本方案使用同主体已认证服务号。由商户平台发起 APPID 绑定，再由公众平台管理员确认；订阅号不能替代本方案的服务号。`WECHAT_PAY_APPID` 和 `WECHAT_MP_APPID` 在当前实现中应填写**同一个已绑定服务号 APPID**：前者用于微信支付下单，后者用于 `snsapi_base` 网页授权取该 APPID 下的 OpenID；`WECHAT_MP_SECRET` 是公众号密钥。Native 也使用该支付 APPID，需获准并绑定。公众号后台还需把站点域名配置为网页授权域名。[JSAPI 开发准备](https://pay.wechatpay.cn/doc/v3/merchant/4015423216)列明认证、绑定及授权目录要求。若开启本站微信 JS-SDK 分享，再配置该域名的 JS 接口安全域名；分享开关与支付开关相互独立。
4. **配置 JSAPI 支付授权目录。** 本站从中文结果页及相关中文付款弹层调起支付，建议在商户平台「产品中心 → 开发配置」配置生产站点的根目录，例如 `https://example.com/`，从而覆盖 `/zh/result/...` 等实际调起页面。目录必须与浏览器中的协议、域名一致，以 `/` 结尾；不能填本地 IP。根目录与精确目录的校验规则见[官方目录说明](https://pay.wechatpay.cn/doc/v3/merchant/4013287088)。
5. **核准 PC 网站与排除 H5。** Native 的 PC 网站场景按[申请指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791875)提交实际域名、ICP 备案及必要的网站授权材料。个体方案不配置 H5 支付域名，将 H5 标记为不适用。若以后变更为具备资格的企业主体，须重新申请 H5 权限和域名，不能沿用个体方案假定已获准。[H5 域名说明](https://pay.wechatpay.cn/doc/v3/merchant/4013287193)
6. **取得 API v3 凭据。** 准备商户 API 证书**私钥**及其序列号、32 字符 API v3 密钥，再从商户后台「账户中心 → API 安全 → 微信支付公钥」取得**微信支付公钥及公钥 ID**。[API v3 概述](https://pay.wechatpay.cn/doc/v3/merchant/4012081606)推荐公钥模式；[公钥获取说明](https://pay.wechatpay.cn/doc/v3/merchant/4013038816)给出后台入口。商户私钥用于本站签请求，微信支付公钥用于验微信的通知和应答，二者不能互换。凭据只写入服务端密钥配置，不发到浏览器、聊天或仓库。

## 第二阶段：配置本站

先部署公开 HTTPS 域名，配置 `DATABASE_URL`、生产 `SESSION_SECRET`，执行数据库迁移并检查 `/api/health`。`APP_URL` 在**构建和运行**时都设成最终来源地址，例如 `https://example.com`，不要带 `/zh` 或末尾 `/`。更换公开域名后重新构建。

在部署平台的服务端密钥设置中填写下列变量；[`.env.example`](../.env.example)是字段清单，不是放真实密钥的地方。

| 变量 | 填什么 |
| --- | --- |
| `WECHAT_PAY_MCHID` | 获批的普通商户号 |
| `WECHAT_PAY_APPID` | 已与商户号绑定的公众号 APPID |
| `WECHAT_PAY_SERIAL_NO` | **商户 API 证书**序列号，不是微信支付公钥 ID |
| `WECHAT_PAY_PRIVATE_KEY` | 与上述序列号配套的商户 API 私钥 PEM；多行可按 `.env.example` 用 `\n` 转义 |
| `WECHAT_PAY_APIV3_KEY` | 商户后台设置的 32 字符 API v3 密钥 |
| `WECHAT_PAY_PUBLIC_KEY_ID` / `WECHAT_PAY_PUBLIC_KEY` | 同一把**微信支付公钥**的 ID（`PUB_KEY_ID_...`）和 PEM，建议成对配置 |
| `WECHAT_MP_APPID` / `WECHAT_MP_SECRET` | 公众号 APPID（与支付 APPID 一致）和公众号密钥，供 JSAPI 取 OpenID |
| `WECHAT_PAY_NOTIFY_URL` | 可留空，默认 `${APP_URL}/api/payments/wechat/notify`；若覆盖，必须是公网 HTTPS 完整路径且不带查询参数 |
| `PRICE_FEN` / `INVITE_PRICE_FEN` / `GIFT_PRICE_FEN` | 人民币**分**，默认 690 / 550 / 490；订单金额由服务端报价决定 |
| `PAYMENT_PROVIDER` | 生产环境在上线前保持 `mock`；先在隔离验收环境修复代码门槛、切到 `wechat` 并重启，真实交易验收通过后再切生产 |

通知 URL 对应仓库的 [`src/app/api/payments/wechat/notify/route.ts`](../src/app/api/payments/wechat/notify/route.ts)。它无需访客 cookie，应允许微信服务器直接 POST。微信[通知地址要求](https://pay.wechatpay.cn/doc/v3/merchant/4012075420)规定公网 HTTPS、完整路径、无查询参数，且不应进行登录态校验。反向代理须正确转发请求信息；仓库的 H5 实现另需真实 `payer_client_ip`，但个体方案不开放 H5。

当前代码也支持留空 `WECHAT_PAY_PUBLIC_KEY*` 后拉取平台证书，但这条路径的首次证书信任尚需单独审查。新接入优先使用微信支付公钥模式，并在上线前完成[API 应答验签](#上线前代码门槛)。不要把“能下单”当成密钥及验签已通过。

## 第三阶段：按顺序验收

先修复[上线前代码门槛](#上线前代码门槛)，然后在隔离的验收环境使用获准的商户配置并设 `PAYMENT_PROVIDER=wechat`。`mock` 只验证本站页面流程，不产生微信侧账单。生产切换前，先处理同一中文站已有的待支付 mock 订单。每个获准入口各做一笔可对账的小额真实订单，依次覆盖正常支付、取消支付和付款后回站。

1. **微信内 JSAPI：** 用真实微信打开 `/zh/quiz`，完成测试，在真实结果页付款。首次尝试应经 `/api/wechat/oauth` 和 `/api/wechat/oauth/callback` 静默获取 OpenID，再回原结果页；确认价格未变、微信收银台显示正确商户和金额、付款后订单变 `paid`，对应完整报告可读。`getBrandWCPayRequest` 的前端成功回调只触发本站查单，不能单凭它解锁。
2. **微信外手机入口：** 在 Safari、Chrome 等手机浏览器验证不再调用 H5 接口，显示明确的微信付款指引；若提供到微信内的续接，验证原结果/订单及访客身份正确恢复，金额与权益不变，且不暴露找回凭据。取消或暂时无法续接时保留原记录，不要求重新测试。H5 真实交易验收在个体方案中标记“不适用”，不能伪造通过。
3. **电脑 Native：** 在中文结果页显示二维码，使用微信**扫一扫**付款，等待页面更新；[Native 产品说明](https://pay.wechatpay.cn/doc/v3/merchant/4012791874)说明不支持以相册识别或长按识别代替扫一扫完成该流程。
4. **逐单对账：** 以本站 `out_trade_no`（订单号）在微信商户平台或[商户单号查单接口](https://pay.wechatpay.cn/doc/v3/merchant/4012526919)核对 `SUCCESS`、微信交易号、人民币分金额与付款时间，再核对本站 `paid` 和报告授权。覆盖原价、邀请价、请 TA 三种价格，以及重复通知、刷新订单页、网络中断后恢复。
5. **异常复测：** 检查取消、超时、通知迟到、已扣款但页面未更新、OAuth 失败、微信外手机入口、公钥或证书轮换。保留原订单号并先查微信账单，避免让买家重复付款。记录一笔真实交易的回调 HTTP 状态、本站事件记录和商户账单作为验收证据；日志中不要写私钥、API v3 密钥或完整 OpenID。

## 常见故障定位

| 现象 | 先核对 |
| --- | --- |
| 个体商户在微信外手机浏览器下单失败 | 个体不支持 H5；先处理浏览器入口，不以反复配置域名解决。按本方案在微信内付款或电脑扫码 |
| 微信内无法调起收银台 | JSAPI 权限、APPID 绑定、支付授权目录；浏览器确实为微信内置浏览器；OAuth 获得的是同一 APPID 的 OpenID |
| H5 报“未配置的参数”或无法回跳（仅未来具备 H5 权限的主体参考） | H5 权限与审核域名、页面实际来源及 `redirect_url` 域名；浏览器不在微信内部；真实客户端 IP。见[官方 H5 常见问题](https://pay.wechatpay.cn/doc/v3/merchant/4012791845)；个体方案不适用 |
| 回调 401 或一直未解锁 | `Wechatpay-Serial` 指向的公钥 ID/证书、API v3 密钥、机器时间、回调公网可达性及反向代理；按商户单号向微信主动查单 |
| 微信已扣款，本站仍待支付或过期 | 保留原订单号和微信交易号，先查微信真实交易状态，再按[上线前代码门槛](#上线前代码门槛)处理差异；不要直接让买家再次付款 |
| 下单报权限、签名或参数错误 | 对照商户号、APPID 绑定、商户证书序列号与私钥是否配套，以及当前渠道是否真正获批；记录微信 API 应答 `Request-ID` 供排查 |
