## 0. 决策摘要与文档优先级

把「双人相处指南」升级为完整报告的重点付费权益：付费前看到具体示例和费用规则；付费后可以直接邀请一个人，把两人的偏好转化为沟通建议。

用户已确定：配对面向付费用户、付款前介绍、付款后增加入口。以下细则是本规格的执行默认值，不冒充用户逐项确认：

| 决策 | 本期规则 |
| --- | --- |
| 谁需要付费 | **双方都需解锁各自用于本次配对的报告**。已向用户询问双付费或仅发起者付费，未收到修改时按此执行；若用户选择后者，先按第 16 节统一改规则再编码。 |
| 买什么 | 现有单次购买包含「该次结果的完整个人报告＋以该次结果发起、参与双人相处指南」。不另售配对商品、不增加订阅、不调整价格。 |
| 价格 | 继续使用结果语言对应的 PRICE_FEN / PRICE_USD_CENTS；当前默认 ¥6.9 / $1，不把数字写死在新文案。两人分别购买自己的报告，不代付、不出现一个价格包两人的暗示。 |
| 单人分享 | P0「我的相处说明书」继续免费，保留原公开、保存、撤销功能；配对是新增付费重点，不把两个功能统称为收费分享。 |
| 权益单位 | 一次测试结果，不是整个浏览器账号。买过甲结果，不能拿未买的乙结果发起或参与。历史已解锁结果直接享有新权益，不另收费。 |
| 发起前置 | 直接从本人已解锁结果发起，不要求先公开单人卡片，不自动代用户创建公开卡。 |
| 人数与次数 | 每份结果最多一条当前有效的新制邀请；同一邀请可供不同好友分别加入，每人与发起人形成独立私密指南，不产生群组。没有按次扣费；不使用「无限、永久」营销承诺。 |
| 历史内容 | 已生成的旧免费双人提示保留原双方阅读及撤回权。旧邀请停止新加入，不批量撤销历史内容。 |
| 内容价值 | 「可能容易理解的地方／需要说清楚的地方／下次可以怎么说」三段；增加具体开口例句与可执行的小约定，无匹配率和关系结论。 |

本文件替代旧 [分享传播规格](./referral-growth-implementation.md) 中「双人提示免费」、邀请必须依附 P0 分享、旧配对入口层级和配对文案的规定；P0 隐私、安全、动画、测试要求继续有效。旧验证记录只证明旧版本，不证明本次付费改造已完成。

本期不做：现金或积分奖励、邀请人数解锁、注册、匿名评价、公开成员榜、婚恋匹配、关系评分、在线 AI 生成、聊天、通知推送、关系类型问卷、双人内容公开海报。真实微信能力仍受既有配置和真机验证状态约束。

## 1. 当前问题与产品目标

### 1.1 已核对的现状

- UnlockPanel、支付弹层的权益主要介绍个人报告，配对不在购买理由中。
- 配对入口位于「我的分享」的单人卡片末尾；用户要先公开卡片，再创建另一份四维公开邀请。
- 邀请页主要展示四维类别和注意事项，缺少具体产物示例，好友不容易理解参与回报。
- 当前 options/create/join/read 均没有配对付费门槛，不能仅隐藏按钮完成收费改造。
- 支付入口会覆盖 URL 查询参数，可能丢失 compare；购买后也没有明确续接配对的路径。

### 1.2 本期要让用户理解的三件事

1. **值得买**：完整报告帮助理解自己，双人指南把这种理解带到一段真实关系中。
2. **值得发**：邀请朋友一起解决一个具体沟通问题，比展示几个类型字母更有参与理由。
3. **值得回来**：双方同意后能读到一份私密、可回访、有开口例句的指南。

这属于待验证的产品假设，不预设转化提升百分比。双付费会增加好友参与步骤，因此费用必须在好友测试前说明，不能到最后一步突然收费。

## 2. 权益与权限矩阵

「解锁」以服务端确认该结果的权益为准。客户端状态、localStorage、URL、付款截图、持有邀请 token 都不能授予权限。

| 身份／结果状态 | 看功能示例 | 单人说明书 | 创建新邀请 | 加入新配对 | 阅读指南 |
| --- | --- | --- | --- | --- | --- |
| 访客、无本人结果 | 可以 | 完成测试后 | 不可 | 先测试及解锁 | 不可 |
| 本人清晰、未解锁结果 | 可以 | 可以 | 提示解锁 | 提示解锁该结果 | 不可读新制内容 |
| 本人已解锁结果 | 可以 | 可以 | 可以，仍需公开同意 | 可以，仍需对照同意 | 仅自己参加的指南 |
| 买过其他结果，本次未买 | 可以 | 可以 | 本次仍需解锁 | 本次仍需解锁 | 不转移其他结果权益 |
| 本人全均衡、未解锁结果 | 可以 | 可以 | 不可购买／发起 | 不可购买／加入新制 | 保留历史已生成记录 |
| 历史已解锁的全均衡结果 | 可以 | 可以 | 可以 | 可以，输出均衡降级内容 | 仅双方可读 |
| 非本人结果或第三人持链接 | 可以 | 不可替别人创建 | 不可 | 不可替别人加入 | 不可读双方私密指南 |
| sample | 可以 | 不可真实发布 | 不可 | 不可 | 只读显著标明的固定示例 |
| 旧制已生成 pair 的原双方 | 可以 | 原规则 | 新邀请执行新规则 | 不从旧邀请新增 | 可回访／撤回原内容，无补款 |

补充规则：

- 个人报告解锁一次后，可用该结果与不同好友各自生成指南；每位好友须满足自己的权益条件，不互相看到参与名单。
- 同一邀请与同一参与者只能生成一份指南，重复请求返回原记录；换参与结果须重新发起一份新邀请，不能覆盖原指南。
- 同一结果已有有效邀请时，显示「继续使用邀请」与「关闭并重新邀请」。后者必须说明会关闭该邀请下的所有指南，不能自动替换。
- 邀请有效期保持 30 日；到期仅阻止新加入，已生成且未撤回的指南继续可读。到期后可为该结果生成新邀请。
- 任一方可以撤回某一指南；发起者关闭整份邀请则其关联指南全部关闭。支付不撤销另一方的隐私控制权。
- mock 支付沿用「演示」标识，可验证功能但不能记作真实收入或真实付费转化。

## 3. 对外命名与价值示例

### 3.1 统一表达

产品名称：**双人相处指南**。英文：**A guide to understanding each other**。

主标题：**把认识自己，延伸到理解彼此。**

简介：看看哪些地方可能容易理解彼此，哪些需要说清楚，再带走一句可以试着说的话。适用于朋友、伴侣、同事，不要求填写关系身份。

关键区别必须讲清：支付解锁使用资格，**对方参与并明确同意之后才生成真实双人内容**。支付成功不得写成「你们的指南已生成」。

### 3.2 支付前固定示例（必须实现）

标识：功能示例 · 使用虚构偏好，不是对你和某位朋友的分析。

题目：**同样是约周末，为什么总聊不到一起？**

- 一方：「先把时间定下来，我才放心。」
- 另一方：「先留一点余地，临时再看看。」
- 解释：「双方对提前确定和保留弹性的需要可能不同。可以把必要节点与可调整的部分分开。」
- 可以试着说：「我们先定一个必须确定的安排，其余留点调整空间，可以吗？」
- 一起试一次：「共同固定一个必要节点，其余安排保留调整空间。」

示例用固定的两份测试 fixture，JP 为相反方向，其余为均衡；用真实指南的同一阅读组件和内容生成器渲染。允许在权益卡只摘取第 2、3 段，在完整介绍页展示全部三段。禁止单独写一套更漂亮但实际不交付的示例布局。

固定示例完整可读，不遮挡真实付费内容，不展示假好友、假配对进度或伪造使用人数。正文使用「可能／可以确认」，不把差异解释成必然冲突。

题目及一方／另一方的对话是固定的场景引子，不是算法对真实关系的识别结果。实际三段正文必须直接使用上述 fixture 经正式生成器得到的内容，不能为营销页另行润色或暗示真实产物会分析用户未提供的周末安排。

## 4. 页面与入口合同

### 4.1 新增公开介绍页 /pairing（英文 /en/pairing）

顺序：现有 AppHeader → 主标题／一句话价值 → 上述完整示例 → 三步流程 → 费用及边界 → 普通 CTA。

三步：「解锁自己的报告 → 邀请对方并各自确认 → 阅读你们的相处指南」。旁边直接说明双方均需解锁对应报告、旧的已解锁报告可直接使用。

主动作「免费开始测试」，次动作「从我的报告继续」。无本人结果上下文时不直接创建订单。不要仅根据前端存储猜最近结果。该页不加页脚或新导航栏，入口来自结果权益卡、现有帮助说明和邀请页的普通链接。

使用 pageMetadata、双语 hreflang、sitemap；新公开文案同步 contentUpdatedAt 与 llms 内容来源。公开介绍页可收录，私密邀请与指南仍 noindex。

### 4.2 本人未支付的真实结果页

顺序调整为：原有结果与四维解读 → **双人指南权益预览** → **现有黑色付费区** → 免费单人说明书入口（次级区域）。保留正常结果阅读，不自动弹支付。

权益预览包含：付费权益标签、主标题、紧凑示例、三段产物名称、「了解双人指南」普通链接。主要购买动作归入现有付费区，不增加第二套支付弹层或固定底栏。

黑色付费区：

- 将「双人相处指南：理解彼此、练习沟通」放在权益列表第一项，其余保留个人报告的优势／盲点、沟通／工作与一周实践价值；图标数组必须同步数量。
- 标题改为「读懂自己，也把理解带进关系。」
- 价格旁说明「本次报告＋本次结果的配对资格 · 无订阅、无自动续费」。
- 相邻可见文字明确「对方也需解锁用于配对的报告；已解锁无需重复购买。双方同意后生成。」不放进默认折叠项。
- 主按钮「解锁报告与双人指南」；手机短文案「解锁报告与配对」，辅助行仍写完整权益。
- 用户可以关闭支付继续免费阅读，不能用配对改造阻断免费概览与免费说明书。

全均衡未支付结果只显示示例和原有说明：「本次倾向尚不明确，暂不提供付费解锁；你仍可阅读概览和生成单人说明书。」保留原答案检查入口，不鼓励为了购买而改变答案。

非本人结果不暴露其是否已购，不显示对方的付费配对入口；可显示通用介绍和「开始我的测试」。sample 仍只引导自己的免费测试，不挂支付按钮。

### 4.3 支付弹层与成功状态

复用 PaymentSheet，不增加支付产品或收款流程。支付前显示完整报告＋配对资格两项、对应结果与价格、双方收费规则；保留全部演示说明、订单凭据和支付方式。

服务端确认成功后：

- 文案「完整报告已解锁，也可以邀请一个人生成相处指南。」
- 普通购买：主要动作仍为「阅读完整报告」，第二个同样可见的动作「邀请一个人」。
- 从邀请续接购买：主要动作「继续这次配对」，次动作「阅读我的报告」。继续后先呈现同意页，不自动配对。
- 关闭弹层后刷新服务端权益，页面变为已解锁状态。等待权益同步时展示进度和重试校验，不提供重复购买按钮。

订单详情页、微信回跳、英文钱包返回也必须提供同样的服务端续接能力，不能只改弹层里的瞬时成功视图。

### 4.4 本人已支付的结果页与报告页

- 已解锁结果页不再展示「购买完整报告」黑色促销区；显示「已包含双人相处指南」权益卡和「邀请一个人」主动作，另保留阅读报告。
- 手机仍只有一个 Dock。未支付显示购买；已支付显示阅读报告＋紧凑的邀请动作，去掉仍在售卖的价格排版；320px 两个动作可收缩／换成短文案，不挤压或产生横向滚动。
- 完整报告顶部在标题信息后加入一张紧凑权益入口，不压过报告标题；第三章「关系」末尾增加同一入口组件。ReportBody 使用可选 server-rendered slot，sample 不注入真实创建动作，四章及两组列表仍完整 SSR。
- 入口传所处的 resultId；服务器重新校验，不相信 prop 上的已解锁标记。

### 4.5 我的报告、我的分享与新的配对中心

新增私密页面 **/my/pairing**（中英同布局）。从已支付结果进入可附白名单 `?result=...`，该 ID 仅在本人页面使用，不进入公开邀请链接。

页面包含三个区域：选择本人结果并发起／我的邀请／我的双人指南。

- 已购结果项提供「邀请一个人」；未购结果项提供「了解配对权益」到其正常结果页，不伪装成可直接创建。
- /my/shares 继续管理免费单人卡片，增加「我的双人指南」链接；原卡片底部配对入口迁往新中心，携带本人结果及可选关联 shareId。
- 旧 /my/shares 中的指南可通过新中心继续访问，不删除旧 /compare/[id] URL。
- 等待中：显示邀请创建日期、截止日期、公开范围、复制／预览／关闭；不猜「好友已看到」「好友付款中」。
- 有指南：显示创建时间与「查看我们的指南」，没有头像姓名时不编造身份；不得显示其他参与者资料给好友。发起者可看到自己拥有的各条记录，参与者只看自己的一条。
- 到期、关闭、撤回各有明确文案。到期可以新建；关闭／撤回不允许客户端恢复旧 token。
- 无通知系统：文案「对方完成后，可在这里查看」，提供主动刷新按钮；不许宣称已通知朋友。

## 5. 发起与受邀全流程

### 5.1 已支付者发起

1. 从结果／报告／我的报告点击「邀请一个人」，进入 /my/pairing，服务端检查本人及该结果权益。
2. 没有有效邀请时呈现实际将公开的四维类别、问卷版本与测试日期，说明任何持链接的人都能读到这些内容。
3. 单独勾选同意，默认不选；原单人说明书的开关不承担本次同意。提示「你的个人报告和具体分数不会公开」。
4. 点击「同意公开并生成邀请」，服务器从本人结果生成冻结快照、192bit token 与 30 日截止日期。
5. 显示邀请预览、复制链接、复制邀请话术、有效期与管理入口。话术只在本地可编辑，不保存任意文本到公开页面。
6. 已有有效邀请直接显示上一步，不重复创建、不自动改变原快照。

默认邀请话术：

> 想和你一起看看，我们哪些地方容易理解彼此，哪些话可以换个方式说。这里能生成一份只给我们双方看的相处指南，需要各自完成测试并解锁用于配对的报告。你确认后才会加入：{公开邀请链接}

本期只交付链接和文本复制；不增加双人内容 PNG。普通 P0 PNG 保持。复制失败提供只读可选 URL／文本，成功只说「已复制」。

### 5.2 好友邀请页 /t/[token]

首屏应明确「为什么参与」以及「需要什么」，顺序如下：

1. 「一起看看，我们可以怎样更好相处。」及三项产物。
2. 发起者明确同意公开的四维信息，标签写「发起人公开的倾向」。
3. 紧凑的固定功能示例，与真实发起者信息视觉分区，明确不是这两人的分析。
4. 规则：「测试和概览免费。生成双人指南前，双方都需要解锁各自使用的报告；已解锁无需再买。」
5. 主动作「使用我的已有结果」，次动作「免费开始测试」；没有本人记录时二者交换主次。无 JS 的入口仍是普通链接。
6. 邀请截止日、范围说明与了解功能链接。

新用户可选择问卷语言，进入原有版本选择，不覆盖草稿。费用按实际选择结果的语言展示，不能把发起人的币种当成受邀者最终价格。邀请介绍先写费用规则；若尚未选语言，可分别标注当前两种语言的配置价格，不暗示等值换算。

OG 标题「一起看看，怎样更好相处」，描述含「双方解锁对应报告并同意后生成」。不在 OG 暴露类别、测试时间、真实结果 ID 或订单。保留 no-referrer、no-store、noindex 与 GA token 页面禁采规则。

### 5.3 好友选择／完成自己的测试

- 已有结果列表显示本人测试时间、问卷与「已解锁／未解锁／本次暂不提供付费」；不因最新一次未买而隐藏较早的已购结果。
- 选择已购结果：先可查看自己的正常结果，再进入配对确认。
- 新做测试：沿用原测验提交和计分；先到正常结果页，再显示「继续这次配对」任务卡，不能直接跳过自己的结果。
- 选择未购且可购买的结果：正常结果页展示其权益与费用；已知邀请关闭时不再以「完成这次配对」诱导购买。
- 受邀者不想付费时，可继续读免费概览、生成个人说明书或离开；发起者看不到拒付或支付状态。

### 5.4 付款后的单独同意

同意页显示自己的四维类别、问卷与日期，说明只向该邀请发起者展示，完整报告／分数／答案不共享。按钮「同意并生成我们的相处指南」。

付费与隐私同意分开；购买、恢复订单、打开链接不视为同意。后端在提交事务中重新检查邀请、双方所选结果权益和本次同意版本。成功后双方从私密页读取冻结内容。

### 5.5 续接、断点与跨设备

- 统一续接参数只接受经过校验的 compare token／站内 continuation ID，不接受任意 returnUrl。语言跳转、打开／关闭支付、阅读本人报告不能无意丢失来源。
- **必须增加服务端续接记录**：在受邀者主动选定本人结果时保存 visitorId＋invitationId＋resultId，最长 30 日且不晚于邀请截止日。测试页只通过现有 compare 参数续接，完成后再登记，不把来源塞入答案或旧草稿。
- 新表 comparison_continuations：id UUID、visitorId FK、invitationId FK、resultId FK、createdAt、updatedAt、expiresAt、completedAt nullable；唯一 (visitorId, invitationId, resultId)，按 visitorId/resultId 查询有索引。提交前核对 invitation 有效、result 本人所有；客户端不能指定 visitorId。
- POST /api/comparison-continuations 幂等登记；只保存续接意图，不表示同意、不授予权益、不创建指南。无权结果 404，失效邀请 410。读由 owner page 调用服务函数，删除／取消只影响续接记录。
- POST 严格输入 { invitationToken, resultId }，由服务器读取 visitor；执行同源检查、8KB 请求体限制和每 visitor 每分钟 30 次限流。成功返回 owner-only 的 { id, status: "pending", expiresAt, continueUrl }，continueUrl 由服务器按站内规则生成。
- 登记和读取待办时先检查该 visitor 是否已加入这份邀请：已有未撤回指南则返回 { status: "completed", pairUrl }，不再次付款或要求同意；已撤回不允许复活。join 成功事务内标记该 visitor＋invitation 下所有未完成续接的 completedAt，防止另一结果的待办继续提示；同一指南的幂等重试也执行这一收尾。
- DELETE /api/comparison-continuations/[id] 只允许当前 owner，同源、限流并幂等删除意图；不撤回邀请或指南。已完成、过期、旧 policy、关联邀请／分享已撤回的记录不作为有效待办。邀请过期不妨碍已生成指南的正常回访。
- 支付返回后按服务端订单的 resultId＋当前 visitor 查询：一条有效记录显示「继续这次配对」；多条显示「选择要继续的邀请」，不按最新一条静默加入。
- sessionStorage/localStorage 失败不影响当次流程；已登记续接不依赖它们。登记失败提供重试与「继续购买个人报告」的明确选择，不能承诺自动续接已保存。
- 换设备仍用现有订单恢复机制重新获得原 visitor，再查服务端续接；未完成身份恢复前不暴露资料。邀请链接不能代替订单恢复凭据。
- 付费时邀请到期／撤回：支付买的是自己的完整报告，权益保留；显示邀请已失效、可阅读个人报告或发起自己的新邀请。不能自动复活旧邀请、虚构好友同意或改配另一个人。

## 6. 真正交付的双人内容

保留当前确定性规则，升级并冻结 **compare-v2**，不引入在线模型或第三方生成。

| 段落 | 标题 | 产物 |
| --- | --- | --- |
| 1 | 可能容易理解的地方 | 一段基于共同倾向的说明；没有共同倾向时诚实使用降级内容 |
| 2 | 需要说清楚的地方 | 一个可能的沟通差异及两种需要，不把任何一方描述成缺点 |
| 3 | 下次可以怎么说 | 一句可直接开口的话＋一件双方可尝试的小约定 |

选择规则沿用 EI → JP → TF → SN：第 1 段优先同向维度，否则均衡降级，否则无共同点降级；第 2 段优先相反维度，其次均衡，否则全相似降级；第 3 段使用第 2 段所选维度，无所选维度时通用练习。

前两段使用现有 compareMessages 的概率型解释，可调整标题；第三段新增 openingLine 与 practice。冻结对象的 contentVersion 分辨 v1/v2，旧 v1 继续原样渲染，不能读取时批量重新生成。

### 6.1 第三段固定例句（实施基线）

| 维度 | 中文开口例句 | English |
| --- | --- | --- |
| EI | 这件事你想现在聊，还是先想一想？我们约个都方便的时间。 | Would you like to talk now or think first? Let's choose a time that works for both of us. |
| SN | 我先说一个具体例子，再说它和整体的关系，你看这样清楚吗？ | I'll start with an example, then explain the bigger picture. Would that help? |
| TF | 我想先听你在意的影响，也一起说清楚我们各自的判断理由。 | I'd like to hear what impact matters to you, and then compare the reasons behind our decisions. |
| JP | 我们先定一个必须确定的安排，其余留点调整空间，可以吗？ | Can we settle one essential part of the plan and leave some room to adjust the rest? |
| 通用 | 这次你最需要我理解什么？我们各说一件，再看看怎么一起试。 | What do you most need me to understand this time? Let's each name one thing and decide what to try. |

practice 沿用并细化已有四维实践；均衡分支也只能询问当前需要，不断言固定偏向。全均衡两人：前两段说明需情境确认，第三段用通用例句。跨版本不比较百分比，附已有版本差异说明。

解释性正文使用「双方／一方／另一方」，避免被冻结的「你」在另一人打开时指代相反；两张类别面板根据服务端 role 标记你与对方。开口例句允许「你／我／我们」，但必须由任一方引用都成立，不绑定发起者身份。没有兼容度、最佳伴侣、谁更理性或关系好坏的结论。

## 7. 服务端权限、接口与事务

### 7.1 统一权益判定

在 server-only 模块集中实现只读的 `getPairingEligibility(resultId, visitorId, tx?)`，返回 owner-only 的 eligible / locked / unavailable / syncing。options、列表和事件上报均只读判定，不触发解锁写入。不得重写计分，sample 永远不 eligible。

- 本人且 results.unlockedAt 非空：eligible；不因全均衡撤销历史已购权益。
- 本人未解锁且允许购买：locked；全均衡未解锁：unavailable。
- 订单已经由服务端确认 paid 但 unlockedAt 尚空：只读资格返回 syncing，禁重复买单、禁提前配对。由现有 owner-only 订单状态查询／显式重试触发独立的服务端修复函数，再重新读取资格；不得从通用 options、列表或统计请求自动修复。
- 修复只能使用服务端已确认 paid 且属于相同 owner/result 的订单；mock 演示订单也能修复演示权益，但不计真实收入。以 unlockedAt IS NULL 为条件幂等补齐，不覆盖已存在的 unlockedAt/unlockOrderId，不重新确认链上交易或创建新付款。客户端支付回调不能自己标记 eligible。
- 非本人／不存在：404，不告诉请求者对方是否买过。

read/list 对新 pair 校验当前 visitor 为双方之一、冻结 policy 为 paid-pair-v2，并查询 invitation.resultId 和 pair.guestResultId 对应本人关系及服务端解锁事实；撤回优先。旧 pair 执行保留既有权益的规则。未加入第三人始终无权，不因已付费任意报告就可读。

### 7.2 接口合同

| 入口 | 新要求 |
| --- | --- |
| GET /api/comparison-invitations/options?resultId=… | owner-only，验证该结果 eligible，返回冻结前公开预览和可复用的有效邀请；不写库 |
| POST /api/comparison-invitations | 接受 resultId、可选 shareId、requestId、consentVersion=compare-host-v2；服务端重新生成快照并核对权益 |
| GET /t/[token] | 仅公开 host 同意的快照及通用规则，不返回原 resultId、订单、内部授权凭据 |
| /t/[token]/join | 根据本人所选结果展示解锁或显式同意状态；未付费不在 HTML/RSC 中生成双方指南 |
| POST /api/comparisons | 原 invitationToken/resultId＋compare-guest-v2；事务中核对新制、有效、非自己、双方具体结果已解锁 |
| GET /api/comparisons/[id] 与 /compare/[id] | owner 是 host 或 guest，资源未撤回；新制权益校验与旧制已生成兼容一致 |
| DELETE 邀请／配对 | 保持 owner／双方授权、幂等及并发撤回规则 |
| POST /api/comparison-continuations | 第 5.5 节的 owner-only 意图登记，不能替代配对创建接口 |
| DELETE /api/comparison-continuations/[id] | 仅本人可取消续接意图，幂等；不改变付款、邀请或指南 |

错误码：401 NO_SESSION；404 NOT_FOUND；403 PAIRING_UNLOCK_REQUIRED；409 PAIRING_ENTITLEMENT_SYNCING；409 INVITATION_UPGRADE_REQUIRED（旧邀请禁新加入）；其余撤回／过期沿用 410 INVITATION_UNAVAILABLE。错误文案中英齐全，前端依据 code 展示对应路径，不能所有问题都变成「稍后重试」。

兼容旧 shareId-only options/create 请求：后端从本人 share 推导 resultId 后仍执行新权限，不能保留免费绕过路径。旧 consentVersion 写入请求返回 409 CONSENT_REFRESH_REQUIRED，引导刷新新范围确认；不把旧同意静默升级。

### 7.3 独立邀请与锁序

comparison_invitations.shareId 改为可空。新主路径只给 resultId；从单人卡显式进入时可关联 shareId，必须属于同 owner、同 result、且未撤销。

- 独立邀请关闭单人卡不受影响；显式关联旧卡的邀请保留「关闭卡片连带关闭邀请和指南」语义，创建确认页说明该关联。
- 主路径不生成隐藏的 P0 分享记录，不伪造公开同意来适配旧外键。
- 保留 owner advisory lock，防相同 requestId、同 result 并发重复创建有效邀请。requestHash 覆盖 resultId、规范化后的 shareId、consentVersion、accessPolicy；相同 key 不同内容报 409。
- 加入／撤回统一锁序：可选 share → invitation → pair。锁后重新检查 policy、撤销、过期、host 所属结果、guest 本人结果及双方权益。
- 所有 innerJoin(resultShares) 都逐项审计改为能处理空父分享的查询，含公开读取、管理列表、事件、报表与撤回。空父分享不是不检查权限。
- 并发加入与撤回：最终撤回后双方不可读，无孤儿 pair；到期后对已有同人同结果幂等读取仍成功，新参与者失败。

使用新的增量迁移，不编辑已经运行的 0004，不触碰 answers、计分、付款候选验证或旧草稿。

| 数据 | 修改与回填 |
| --- | --- |
| comparison_invitations | share_id nullable；新增 access_policy，旧行 legacy-free-v1，新写 paid-pair-v2；保留 result_id、快照与同意版本 |
| comparisons | 新增 access_policy；旧行 legacy-free-v1，新行 paid-pair-v2；contentVersion v1/v2 分辨冻结产物 |
| comparison_continuations | 新表，字段及约束按 5.5；不是权益表，不携带订单号或答案 |

| share_events | 新增 invitation_id nullable FK 和时间查询索引；邀请事件以 invitation_id 为传播来源，pair_view 可同时带其 pairId；不能同时填 share_id 和 invitation_id。新增 owner_result_id nullable FK 与 eligibility_at_event nullable enum，用于本人权益曝光漏斗，不能出库给第三方 |

历史处理顺序：先回填旧 policy，再确保新代码写入固定 paid-pair-v2；默认值与数据库 CHECK 不能允许新写漏 policy 被当作旧免费权限。停用旧写路径后上线新写入。

旧邀请页面显示「邀请方式已更新，请发起者重新创建邀请」；发起者本人有直达升级入口，其他人没有创建权限。不要为此设置旧行 revokedAt，否则会错误关闭旧指南。原 host 未支付须先解锁原结果；已支付者只需新同意并创建。

旧免费 pair 只保留既有双方查看／撤回，不允许凭旧邀请继续新增，也不自动升级成 v2 内容。已关闭的旧内容不恢复。新制旧制列表显示一致但可加「历史指南」标识。

数据库只能在确认的本地／测试环境迁移。验收必须核对**运行服务实际连接的库**具备新列与新表，再验证接口，不能重复出现测试库迁移完成而用户本地库缺表的问题。缺迁移不得静默回退成免费权限。

## 9. 统计与效果判断

### 9.1 最小新增采集

复用已有 GA 初始化、quiz_start、购买事件和 first-party share_events；不新增第三方 SDK。

| 事件／事实 | 记录规则 |
| --- | --- |
| pairing_benefit_viewed | 本人真实结果权益区域可见时，每 visitor/result/UTC 日去重；只记录归属已核实的 owner_result_id、服务器计算的 eligibility_at_event 及白名单 surface、locale、规则版本，不采集测试内容 |
| pairing_entry_clicked | 点击邀请／了解权益；按真实点击记录，不能等同生成 |
| pairing_checkout_opened | 复用现有支付弹层的实际打开触发点补 first-party 事件；每 visitor/result/UTC 日去重，服务端验证 owner_result_id；不重复发送 GA begin_checkout |
| pairing_result_selected | continuation 首次成功登记时服务端记录，包含 invitation_id、owner_result_id，按 visitor/invitation/result 去重；不依赖续接表长期留存 |
| pairing_resume_clicked | 从支付返回选择继续邀请；客户端传 continuationId，服务端校验本人并推导 invitation_id／owner_result_id；不等于同意 |
| 邀请创建成功 | 以 invitation 表持久事实计数，网络重试不重复；区分新 paid policy |
| 配对生成成功 | 以 comparisons 表的唯一 pair 事实计数，不由客户端上报替代 |
| 阅读／复制 | 复用 comparison_viewed、复制意图／成功；不给复制或下载起名 share_success |
| 真实付款 | 以现有订单 DB 为准，排除 mock；不同币种分别统计 |

以上交互事件进自有 DB。本人结果事件的客户端仅传 resultId，服务端验证所有权、判定资格后落 owner_result_id；客户端传来的资格值一律忽略。公开介绍页的通用点击无本人结果归属，不进入结果购买漏斗。新事件走独立的判别分支，不能强迫它伪造 shareToken 来适配旧事件 schema；更新请求校验、限流、dedupe 与 docs/analytics。

若复用 GA 仅允许通用 CTA 名称／位置；token、pairId、resultId、订单号、公开类别、分数、双方关系不发送给 Google。/t、/compare 等能力 URL 继续禁采；新 /my/pairing 及查询参数先完成清洗测试。支付续接 token 不进入钱包外链和支付供应商参数。

### 9.2 两条漏斗分开看

**购买漏斗**：符合购买条件的未购结果权益曝光 → 打开原支付 → 对应该结果真实支付。去重单位为 visitor/result；7 日成熟窗口。使用已有订单事实，不新增重复 purchase。不要把同一 visitor 买其他结果算入本结果转化。

窗口从该结果首次 eligibility_at_event=locked 的权益曝光开始；订单 paidAt 必须落在 [首次曝光, 首次曝光＋7 日) 且属于该结果，才计为窗口内购买。按 UTC 查询，报告截止时不足 7 日的单列观察队列；不能把后来某日曝光改作起点以追领转化。

**配对漏斗**：新制邀请创建 → 非本人可见触达 → 有效选定本人结果 → 必要时解锁 → 双方同意生成 → 双方至少各查看一次。已付费来访者进入「使用已有结果」分支，不能误记成新购买。

核心指标：邀请发起率（有资格且看到入口的结果中创建邀请的比例）、14 日成熟邀请完成率（至少生成一份指南的邀请／成熟新制邀请）、双方阅读率（生成后 7 日两人都读过／成熟指南）。报告各步流失，包括「知道需要付费后离开」，不把双付费一定提高收入写成结论。

14 日完成率仅计 pair.createdAt 落在 [invitation.createdAt, ＋14 日) 的至少一次生成；双方阅读率仅计两方各自的 view.occurredAt 落在 [pair.createdAt, ＋7 日)。超过相应窗口的生成／阅读单列，不回填成熟转化率。邀请发起率按同一结果首次 eligible 曝光后的 7 日窗口计算，分母中排除曝光前已有有效新制邀请的结果；观察中队列不与成熟队列混合。

来源归因仍是 7 日首次有效触达与首次测试完成，自有 DB 为准：P0 分享来源与新独立邀请来源用互斥的 shareId / invitationId 区分，先到的有效窗口不被后来来源覆盖。统计失败由 savepoint 隔离，不阻止有效测试提交。

已有结果的人可以参加配对，但不算首次测试推荐。旧表无法区分历史邀请和卡片触达，不回填猜测；归因窗口覆盖造成的历史缺口仍需在报表披露。新增漏斗按新规则启用后采集，不能与旧免费数据直接混合比较效果。

只读报告升级口径版本并分开呈现单人卡片、付费邀请、旧制 pair、新制 pair。事件留存沿用原 90 日，归因清理沿用原规则，续接记录到期／完成后 30 日可清理；不删除报告、订单、邀请或指南。

## 13. 验收清单

### A. 商业表达与完整流程

- 未购真实结果在支付前看到具体示例、完整报告＋配对资格、双方费用要求；可以继续免费阅读。
- 已购结果／报告／我的报告有明显邀请入口；不要求先公开单人卡；不仍显示购买价格 Dock。
- 支付完成只表示资格开通，对方未同意前不出现真实指南。
- 已购旧结果可用，未购新结果不可借权；不同币种按所选结果处理，演示支付标签完整。
- 好友在开始测试前知道费用规则；原测试结果先正常呈现，付款后再次同意，发起者看不到好友付款行为。

### B. 权限、隐私与一致性

- 无 cookie、伪造 cookie、非本人 result、sample、客户端 unlocked=true、直接请求 API 都不能绕过。
- 双方付费四组合分别测试：未／未、已／未、未／已均拒绝新增；已／已且双方同意才成功。
- 公开 HTML/RSC/OG 无 resultId、订单、分数、答案、未公开字段；第三人连同 pair URL 也不能读。
- 独立邀请、带 share 关联邀请、旧免费邀请、旧已生成 pair 分别验证读取／撤回语义。
- 同一 requestId 重试只生成一次；跨 result 重用冲突；同结果同时发起只有一个有效邀请。
- 并发加入／撤回、撤回／重复读取、到期前后边界有真实 DB 测试；撤回后最终无访问窗口。
- 订单 paid 但权益未同步时可幂等修复或明确同步失败，禁止重复购买；失败日志不输出凭据。
- 邀请在支付中失效时不丢个人报告、不自动加入他人；恢复身份不自动同意。

### C. 内容、语言、降级与统计

- 同向、相反、部分均衡、全均衡、无共同点、无差异、跨问卷和中英组合输出正确；无匹配率。
- 示例显著标识且同真实组件，中文不夹英文装饰，英文无中文 fallback。
- 清除／拒绝本地存储、断网、复制失败、生成中关闭、重复点击后状态可恢复。
- 续接多条不串人；中文／英文切换、微信 H5 回跳和英文钱包恢复各记录验证结果，不能用普通浏览器测试冒充真机。
- 首次归因 savepoint 故障注入通过；两类来源不双计；mock 排除；过期／老数据口径明确。
- no-JS/print/reduce 完整，CTA 首帧可点，不重播、不等动画结束才更新权限。

## 14. 发布、回退与限制

- 必须把权限、迁移、双语规则、支付前后入口和续接作为一个完整交付；只上线营销而真实功能未开放不算完成。
- 发布需运维先应用增量迁移，再切到新写入版本；不要让旧进程与新进程同时接受创建邀请／加入写入。用户明确要求部署时再制定该环境的切换步骤。
- 回退只能关闭新建／加入入口并保留读与撤回服务，不回滚到可免费加入的旧服务；新增表与历史已购数据不自动删除。
- 本期不实现退款系统。若未来新增退款／权益撤销，须另定双人内容处理规则并在服务端同步，不能只改前端显示。

## 16. 若用户选择「仅发起者付费」

这是互斥的政策变更，不做同时展示的套餐：主规格将统一换成 host-paid-v2。

- host 必须解锁本次结果；guest 本人结果无需付费，仍须单独同意，guest 可免费读取自己参与的这一份指南。
- guest 想发起另一份邀请，才需要解锁其发起结果；自己的完整个人报告仍按原价付费。
- 邀请页直接明确「发起者已解锁，你可免费完成测试并参与」，但不泄漏订单或支付方式；购买页明确邀请资格由谁支付。
- 删除 guest 为配对必须付款的步骤和对应漏斗门槛，续接记录仍服务测试／跨设备恢复；保留个人报告自愿购买。
- 调整权限组合测试、已生成 pair 的 policy、指标分母和全部中英收费文案；不能只改按钮文案或只放开 join API。

选择该变更须先更新本文件决策摘要与所有引用；执行者不自行切换商业规则。
